# บทเดโม 3–6 นาที (ควรใช้ class proxy จริงก่อนส่ง)

ไม่ต้องอ่านตามทุกคำ ใช้เป็นลำดับและอธิบายด้วยภาษาของตนเอง ห้ามเรียก offline demo ว่าเป็นการเรียก LLM จริง

## 0:00–0:40 ปัญหาและข้อมูล

“ผมทำ GearMate เพื่อช่วยตอบคำถามยืมอุปกรณ์ มีทั้งกฎที่เป็นข้อความและสถานะในตาราง ข้อมูลชุดนี้ผมสร้างเป็นชมรมสมมติใหม่ มี 18 นโยบายและ 12 อุปกรณ์ ไม่ใช่ข้อมูลชมรมจริง”

## 0:40–1:50 Success case

ตรวจป้าย Class proxy ก่อน ถ้ายังขึ้นโหมดสาธิตให้บอกตรง ๆ และอย่าส่งเป็น live demo สุดท้าย ถาม “กล้องว่างกี่ตัว และต้องวางเงินประกันเท่าไร” เปิด tool trace ให้เห็น search_docs กับ query_inventory เปิด citation และแสดงว่าจำนวนตรงกับคลัง ต้องได้ 2 กล้องใน snapshot นี้ และประกันกล้อง 300 บาท ถ้าโมเดลตอบต่าง ให้บันทึกเป็น failure ไม่ตัดต่อกลบ

## 1:50–2:40 Architecture

เปิด `app/agent.py` อธิบาย model ขอเรียก tool, โค้ดตรวจ arguments, ส่ง role tool พร้อม ID, แล้วเรียกโมเดลอีกครั้ง แสดง max_steps และการห้ามเรียก tool นอก allow-list

## 2:40–3:40 Evaluation

เปิดหน้า “ผลประเมิน” และรัน `python -m scripts.evaluate` ให้ดูว่า baseline top-1 recall=.8000 ส่วน top-3=.9833 hybrid=.9833 เท่ากันที่ k=3 จึงเลือกวิธีง่ายกว่า บอกว่าตัวเลขนี้เป็น retrieval ไม่ใช่ faithfulness ของ LLM และ test set ยังไม่มี independent labels

## 3:40–4:40 Failure case

แสดง t27 ในหน้าประเมินซึ่งค้นหลักฐานสองเรื่องได้ไม่ครบ แล้วถามคำถามใหม่ เช่น “ยืมได้กี่วัน” หรือ “มีโดรนให้ยืมไหม” อธิบายว่า lexical search อาจพลาดคำสั้น และไม่มีข้อมูลโดรน ลองถามให้ชัดขึ้นได้ แต่การแก้ query ไม่ใช่การทำให้ระบบรู้ทุกเรื่อง

## 4:40–5:10 ข้อจำกัดและต่อยอด

“ขั้นต่อไปคือเก็บคำถามจากผู้ใช้อีกคน ตรวจ labels และคำตอบด้วยคน ทดลอง multilingual embeddings หรือ reranker แล้วเทียบที่ context budget เท่ากัน รวมถึงต่อข้อมูลชมรมจริงเมื่อได้รับอนุญาต”

อัดหน้าจอพร้อมเสียง 3–6 นาที แล้วอัปโหลด YouTube แบบ unlisted หรือ Drive ตามโจทย์ ไม่ควรอัด `.env` หรือ key และไม่ต้อง deploy endpoint ที่ไม่มี authentication ออกอินเทอร์เน็ต
